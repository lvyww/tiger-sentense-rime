# 紧凑排序先验 — 2026-09-15

目标是在不扩大 214 MiB TCSKNM02 模型、不加大 Beam 的前提下，利用输入码本身和
一个很小的词存在性结构修正 Top-1。实现不改变字符 n-gram、候选 lattice、Beam
宽度、学习权重或自动上屏阈值。

## 实现

最终分数在原评分上增加三类只用于排序的证据：

1. **逐字主码证据**：未显式选重、且码段是该字正常主码的单字边，按
   `2.0 × 码长` 加分。这是 `P(code|character)` 的近似；多字码表边不领取该分。
2. **完整码保护生僻字**：原规则对字频 3000 以后、左右均无已观察 bigram 的字
   扣 2 分。现在只有主码或显式选重的 **4 码及以上**单字边免除此项；2～3 码
   保留原惩罚。
3. **紧凑词先验**：从上游词库选取 50,000 个可编码的 2～4 字高频词，存成
   150,032 字节 Bloom filter。只重排原 Top-5；非重叠最大词覆盖中，2/3/4 字词
   分别投 `0.10 / 0.12 / 0.14` 分。

码形分在路径上累计，但不写入 Beam score；生僻字保护只在终点评价；词先验只看
已经生成的 Top-5。三者都不写入 `mass_score` / `confidence_score`。因此 Beam
候选集合和提前上屏概率仍由原字符模型决定。没有 n-gram 模型时三项全部关闭，
原来的「码表名次 → 更少边 → 分数」降级排序不变。

Bloom filter 不存词文本和词频。假阳性估算为 `2.11e-5`，且一次假阳性只产生上述
有界小票。来源、转换和许可见
[`LEXICAL_PRIOR_ATTRIBUTION.md`](LEXICAL_PRIOR_ATTRIBUTION.md)。新增的两个主要
运行时文件为 150,032 字节 filter 与 5,319 字节 Lua reader，合计 155,351 字节；
再计入主解码器与 schema 的净增源码，本次未压缩运行时文件总增量为
169,804 字节（约 165.8 KiB）。

## 定向差异集消融

模型：TCSKNM02，SHA-256
`79591aaf111ddcdbf9301755f351788ff7107abe629cfb1290abb9572fa9c413`。
输入由当前码表为目标文本逐字选择正常码，关闭逐键提交，只比较最终解码。

| 配置 | 正向 847 Top-1 | 正向 Top-5 | 正向 Top-20 | 反向 122 Top-1 |
| --- | ---: | ---: | ---: | ---: |
| 旧评分 | 63 | 808 | 844 | 116 |
| + 主码 `2.0/键` | 142 | 825 | 846 | 121 |
| + 仅 4 码生僻字保护 | 179 | 828 | 846 | 121 |
| + 50k 词先验 `0.1`（最终） | **182** | **828** | **846** | **121** |

相对同一直接解码基线，最终配置在正向集救回 119 条、在反向集救回 5 条；两边
合计 124 条，基线正确样本中 **0 条倒退**。词先验本身额外改变 3 个首选，三条
均由错变对：

- `居籍桁简 → 居简而行简`
- `九隔槁下排引流注 → 九随地高下排引流注`
- `自己的斤两也能换点量地出了 → 自己的斤两也能掂量地出了`

没有直接采用“所有主码都免生僻惩罚”：2 码起免罚虽把正向 Top-1 推到 228，
却让两组基线正确样本合计出现 4 条倒退；反例的错误生僻字均只用了 3 码。
把门槛收紧到 4 码后，这四条全部恢复。

另对码表中 126 个“首选多字快捷边 × 前后文”组合做保护测试：旧评分正确 125 个，
最终主码权重保留 125 个，倒退 0。对旧 Top-20 缺失的三条逐一把长句 Beam 从
48 提到 96、200、500，乃至全程 2000，均未把目标带回 Top-20；本轮因此不增加
移动端 Beam。

## 解码开销

Linux x86-64、Lua 5.4、同一生产模型下，各跑 10 次的本地 CPU 微基准：10 个固定
40 键随机串的整段 P50 从 14.93 ms 增至 18.96 ms，折合约 `+0.10 ms/键`；
逐键 P95 从 1.06 ms 到 1.24 ms。命名的 40 码低置信样本，完整一次最终解码 P50
从 5.98 ms 到 6.32 ms；模拟 frontend 的整段 P50 从 10.80 ms 到 16.66 ms，
折合约 `+0.15 ms/物理键`。测试是独立进程 CPU 时间，存在页缓存和 GC 离群值，
不能替代 iOS 真机墙钟延迟。

词先验最初对 Top-20 全部打分时开销明显更高；最终限定为 Top-5，并让五个候选
共享一次短词查询缓存。上面数据对应收缩后的实现，Top-1/5/20 与 Top-20 版本相同。

## 解释边界

这 969 条是由“魔虎和虎整至少一方出错”筛出的差异样本，不是随机测试集；其中
正向 847 条更是特意选择了旧虎整错误。因此上表用于参数消融和回归保护，**不能**
外推成 49,794 句全量准确率。原比较采用逐键与提前上屏，本工具采用最终整句解码，
所以旧评分只重现其中 756 条历史首选；应比较同一工具下的 63→182，而不能把
182 直接称为“修复了历史 847 条中的 182 条”。完整语料未包含在两个结果文件中，
取得原 49,794 句后仍须再跑一次端到端验收。

## 复现

结果清单不提交到本仓库。取得两份 Markdown 后：

```sh
# 旧评分
lua tools/evaluate_contrast_sets.lua . huzheng_wrong_mohu_right.md \
  --set canonical_code_reward=0 \
  --set lexical_prior_weight=0 \
  --set canonical_isolation_factor=1 \
  --set canonical_isolation_min_code_length=2 \
  --dump-candidates baseline.tsv

# 当前默认评分
lua tools/evaluate_contrast_sets.lua . huzheng_wrong_mohu_right.md \
  --dump-candidates current.tsv

python3 tools/compare_contrast_dumps.py baseline.tsv current.tsv
lua tools/evaluate_phrase_edges.lua . 2
```

工具只读输入清单和模型。`--set` 还可扫描 Beam、字符奖励、rank penalty 与
isolation 参数；不会改写部署文件。
